# OctoAcme Project Management Process Docs

This directory contains the core guidance for how OctoAcme manages projects from idea through delivery, release, and continuous improvement. The documentation is designed to help teams align around clear roles, shared workflows, and decision-making practices so that work remains consistent, transparent, and measurable across projects.

If you are new to OctoAcme, start with the project overview and personas documents to understand the overall model and the responsibilities of each role. From there, use the lifecycle guides to navigate the specific processes for initiation, planning, execution, risk management, release, and retrospective work.

## Core Principles

- Customer-first: prioritize customer value and usability
- Iterative delivery: deliver small, testable increments
- Clear ownership: each project has a named Project Manager and Product Lead
- Data-informed decisions: measure impact and iterate based on evidence
- Psychological safety: encourage feedback, learning, and candid discussion

## Core Roles and Responsibilities

| Role | Responsibilities | Typical Focus |
| --- | --- | --- |
| Project Manager | Coordinates schedules, risks, dependencies, learning, and communication across the team and stakeholders | Delivery planning, reporting, and alignment |
| Product Manager | Defines outcomes, priorities the backlog, and measures value delivered | Product strategy, goals, and acceptance criteria |
| Developers | Build, test, review, and maintain software components | Implementation, technical quality, and maintainability |
| QA / Testing | Validate quality, acceptance criteria, and release readiness | Test coverage, validation, and risk reduction |
| Stakeholders | Provide inputs, approval, and business context | Decision-making, prioritization, and sponsorship |

For detailed role descriptions and communication patterns, see [OctoAcme Personas](./octoacme-roles-and-personas.md).

## Standard Project Management Workflow

1. Initiate the work by validating the problem, clarifying success metrics, and aligning stakeholders.
2. Plan the effort by creating a backlog, estimating work, identifying dependencies, and confirming milestones.
3. Execute in short cycles with standups, project board updates, PR reviews, and ongoing quality checks.
4. Track risk, dependencies, and stakeholder communication through regular reporting and escalation paths.
5. Release with a documented checklist, smoke testing, and rollback readiness.
6. Close with a retrospective to capture learnings and convert them into actionable improvements.
